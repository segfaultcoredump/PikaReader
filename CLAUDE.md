# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

PikaReader is a Java 21 / Maven app (v0.7, GPL-3.0) that runs on a small SBC (e.g. Raspberry Pi) next to RFID readers (Impinj Speedway R220/R420 and R700/R720 via Octane SDK 6.0.0.0, Zebra FX7400/FX7500/FX9500/FX9600/FXR90 via raw LLRP). It gates and stores tag reads on disk, streams them over a websocket, and supports "rewind" so a timing app can re-download reads later.

## Commands

- Build: `mvn package` (`mvn` isn't on PATH on the dev Mac; use NetBeans' `"/Applications/Apache NetBeans.app/Contents/Resources/netbeans/java/maven/bin/mvn"`, add `-o` to build offline) → `target/PikaReader-0.7.jar` plus a shaded `target/PikaReader-0.7-uber.jar` (shade plugin attaches classifier `uber`)
- Run: `java -jar target/PikaReader-0.7-uber.jar` (or `mvn exec:java -Dexec.mainClass=com.pikatimer.pikareader.PikaReader`). Stop with Ctrl-C / SIGTERM / SIGHUP (a JVM shutdown hook in `PikaReader.start()` stops readers and HTTP).
- There are no tests (`src/test/java` is empty) and no lint configuration.
- Config file: `~/.PikaReader.cfg` (JSON), override with `-DCONFIG=<path>`. Tag DB directory: `~/.PikaReader`, override with `-DDB=<path>`. A default config is generated on first run (default reader IP `192.0.2.10`); edit it and restart. Web UI/API listens on port 8080.
- Log file: `<java.io.tmpdir>/pikareader.log`, override with `-DPIKAREADER_LOG=<path>`. A new file starts each run (`StartupTriggeringPolicy` + logback fixed-window rolling); the last 5 runs are kept as `.log` and `.log.1`–`.4`. Configured in `src/main/resources/logback.xml`.

## Architecture

- **Singletons**: `PikaConfig`, `TagDB`, `ReaderHandler`, `ProfileManager`, `HTTPHandler`, `StatusHandler`, `TagReadProcessor`, `TagReadRouter` all use the SingletonHolder idiom. Startup order is in `PikaReader.start()`.
- **Reader plugins**: `RFIDReader` is the interface. Implementations are annotated `@AutoService(RFIDReader.class)` and discovered via `ServiceLoader` in `ReaderHandler`, keyed by `getType()`, which must match the `"Type"` in the config's reader entries. `Impinj` (Octane SDK, listener classes in `readers/impinj/`) and `Zebra` (raw LLRP via the `org.llrp.ltk` classes bundled in the Octane jar, in `readers/zebra/`) are the real implementations; `LLRP` is an empty stub. Each configured reader is its own instance with its own connection and threads; `"Index"` must be unique.
- **Reader profiles** (`readers/profiles/`): one profile (`start_mats`, `start_side_panels`, `finish_mats`, `finish_side_panels`, `split_side_panels`) applies to every reader. All values live in `src/main/resources/reader-profiles.json`; don't hard-code them in Java.
    - `ProfileManager` loads it and only reads `PikaConfig`, so drivers call it from their connect threads. It persists `"Reader"` → `"Profile"` (default `finish_mats`) and `"Region"` (`Auto` or a region family), and assigns sessions: 2, 3, 2, 3… by `Index` with several readers, random 2/3 with one (the user's rule, not the spec's layout table). `ReaderHandler` calls `assignSessions()` before creating readers.
    - Per-reader overrides live in the reader's `"Profiles": {"<id or name>": {...}}`. Override > profile default; the old reader-level `Reader Mode`/`Search Mode`/`Session`/`Tag Population` are ignored with a warning (`checkReaderConfig`).
    - `RFIDReader.applyProfile()`/`getProfileSettings()` are default methods. `ReaderHandler.setProfile()` (synchronized with start/stop) refuses while reading, saves, then calls `applyProfile()` on every reader. API: `GET /profiles`, `GET /profile`, `PUT /profile/{profile}` (404 unknown, 409 reading). `/status` only carries `profile: {id, name}`.
- **Zebra driver**: `ZebraConnectionMonitor` (one virtual thread per reader) owns connect/reconnect and resumes reading. The LTK never reports a closed session, so `Zebra` hooks `sessionClosed` and also watches keepalives. `LLRPConnection.transact()` is not thread-safe (all commands go through `Zebra.commandLock`) and must never be called from `ZebraMessageHandler`, which runs on the MINA IO thread. LLRP 1.0.1 ROSpecs don't loop, so `DualTarget` restarts the ROSpec on each End_Of_ROSpec with a non-blocking `send()`. The shared `readers/ReaderClock` derives the reader→local-clock offset (min-filter over 60 s) from event and tag timestamps: `DELTA` mode corrects reads to local time, `READER` mode (Zebra `"Clock": "NTP"`) uses reader time as-is and warns on >1 s skew. LLRP cannot set a Zebra clock. Profiles pick the link with `ZebraLinkMatcher` (link classes from the JSON matched on M, BDR, PIE and Tari range/step, then the class's `nearest` rule for tables with no exact match, e.g. the FX7400; never the automac index; sets `C1G2RFControl.Tari`); `ZebraReaderMode` still matches named modes or raw indexes for `Reader Mode` overrides, since Zebra mode IDs differ from Impinj's. `resolveProfile()` runs on each connect and profile change (`applyProfile()` deletes and re-adds the ROSpec). The default search mode `AB_FLIP` is one state-unaware AISpec with Zebra's custom `MotoAntennaConfig` (vendor 161, subtype 703 holding 704 stop condition = u8 trigger + u16 cycles, and 710 query config = 16 bits, SLAll bit 0/ABFlip bit 1, i.e. `0xC000`), hand-encoded in `ZebraMotoParams` because the LTK has no Zebra extensions. `AB_FLIP` is built from an `AbFlipPlan`: Zebra query config or the standard "Select reset" (zero-length-mask `C1G2Filter` setting the session flag to A, state-aware singulation on A), and Zebra stop condition, one AISpec per antenna (`Tag_Observation` N-attempts trigger; the ROSpec ends each cycle and `onROSpecEnded()` restarts it, like DualTarget), or none. `addROSpec()` tries the plans in order, then `DUAL_TARGET`, then `READER_DEFAULT`, and caches what was accepted per serial|firmware in the static `ACCEPTED` map (in memory). The optional per-reader `"Model"` picks `model_support` in the JSON; FX7400/FX9500 are `antenna_extensions: unsupported` (Zebra ICG Table 4), so their Zebra-parameter plans are skipped. `verifyROSpec()` reads it back with `GET_ROSPECS`. LTK 13 (Octane 6) facts: the IO handler auto-answers KEEPALIVE with a KEEPALIVE_ACK carrying the KEEPALIVE's message ID; `exceptionCaught` reports errors to `errorOccured` as `"<ExceptionClass> : <message>"`, which `Zebra.onLinkError` string-matches (errors while still connecting are kept in `connectError` and added to the failure log); the deprecated `LLRPConnector.reconnect()` is still called by `send()`/`transact()`, so the override that returns false is still needed.
- **Impinj driver**: `Clock`, `TLS`, `Port`, `Power Level` and `Antenna Config` are per-reader config; inventory settings come from the profile via `ImpinjProfile.resolve()` (R700/R700v2/R720 use the `impinj_r700_series` region tables, everything else `impinj_speedway`, whose candidates end in mode 2 for the R220; `model_support` adds the R220's region list and role warnings, which surface in `getProfileSettings()` `warnings` and the web UI's profile-change result; an R700 whose region is unknown or contradicts `"Region"` gets the reader's default mode). `connect()` sets up listeners and calls `configure()`, which `applyProfile()` also uses. Octane 6 removed the `ReaderMode` enum: RF modes are plain integers (`Settings.setRfMode(Integer)`, `FeatureSet.getRfModes()` = the reader's LLRP RF mode table, which usually omits the AutoSet modes); `ImpinjRfMode` holds the names, unknown numbers (e.g. R700 modes 141, 288) pass through. `configure()` tries the profile's RF mode candidates in order with `applySettings`, then falls back to `setRfMode(null)` (= the reader's own default), and reads the settings back with `querySettings()`. The SDK's `isConnected()` is true while a connect is still in progress. `"Clock": "Local"` (default; `"Pi"` and `"Delta"` are accepted aliases) sets the reader clock from the local clock over SSH (RShell, `root`/`impinj`) and disables reader NTP; `"NTP"` leaves it alone. Both use a `ReaderClock` in `READER` mode for skew warnings. Octane 6 bundles the mwiede JSch 0.2.x, which dropped `ssh-rsa`, SHA-1 kex and CBC ciphers; `Impinj`'s static initializer appends them back to JSch's global defaults so older Speedway SSH still works. `ImpinjConnectionLostListener` must reconnect through `Impinj.connect()` (the SDK's no-arg `connect()` ignores port/TLS).
- **LLRP over TLS**: `readers/LlrpTls` (`"TLS": true`, default port 5085). The LTK's TLS already trusts any certificate and skips hostname checks; `LlrpTls.allowLegacyCertificates()` also clears `jdk.certpath.disabledAlgorithms` / `jdk.tls.disabledAlgorithms` (JVM-wide, must run before the first TLS connection, so it's called from each driver's `create()`).
- **Tag pipeline**: `ImpinjTagReportListener` / `ZebraTagReportHandler` → `TagReadProcessor` (called concurrently from every reader's IO thread) (100k-entry queue; gates by `Gating` seconds and `Gating Style` ANTENNA/BOX/READER, keeping the strongest read per key) → `TagReadRouter` (applies `ChipFormat` hex/decimal) → fan-out to `TagDB.addReads` (on-disk JSON lines at `/yyyy/MM/dd/HH/HH-mm-ss.SSS.dat`, only today's files are loaded into memory at startup; `/rewind/{from}[/{to}]` reads older days from disk via `TagDB.getReadsBetween`) and `HTTPHandler.sendTags` (websocket `/events`).
- **HTTP**: `HTTPHandler` uses Javalin 6.7. REST: `/start /stop /trigger /rewind[/{from}[/{to}]] /debug /status`; websockets `/events` and `/status`; static UI in `src/main/resources/public`. `StatusHandler` aggregates per-antenna stats, `DiscoveryListener` answers UDP broadcast discovery, `DebugLogHolder` backs `/debug` through logback.

## Gotchas

- A "trigger" is a special read with chip/reader/antenna all 0.
- JSON uses `org.json` throughout; a Jackson migration is listed in `TODO.md`.
- `com.impinj:octane-sdk:6.0.0.0` must be resolvable by Maven to build. It's the SDK's jar-with-dependencies (also the source of the LTK, MINA, JSch and slf4j-api classes), installed locally with `mvn install:install-file -Dfile=OctaneSDKJava-6.0.0.0-jar-with-dependencies.jar -DgroupId=com.impinj -DartifactId=octane-sdk -Dversion=6.0.0.0 -Dpackaging=jar -DgeneratePom=true` (don't use the SDK's own pom: its `libltkjava` dependency isn't resolvable).
